# 깔끔 시험지 프로젝트 규칙

[프로젝트 배경]
나는 수학 학원 강사다. 학생이 푼 수학 시험지를 사진으로 찍어 올리면,
학생의 필기(연필/볼펜 풀이, 답 체크, 동그라미, 빨간펜 채점 표시)를 지우고
인쇄된 문제 글자와 그림(특히 함수 그래프·도형)만 원래 양식 그대로, 더 진하게 남기는
웹사이트를 만들고 있다. 이후 깨끗해진 시험지를 읽어 변형 문제와 해설지도 자동 생성한다.
쓰는 사람은 우리 학원 강사 몇 명이고, 학원 내부 서버(또는 내 노트북)에서만 접속한다. 외부 공개는 하지 않는다.
로그인·결제 없이, 강사가 **각자 자기 Anthropic API 키를 화면에 넣어 쓰는 방식(BYOK)**이다.
학습 데이터는 학생이 푼 시험지 사진만 있고, 깨끗한 원본은 없다.

[기술 원칙]
- 언어: Python 3.11
- 이미지 처리: OpenCV, NumPy, scikit-image, Pillow
- 웹: FastAPI + 단일 HTML 페이지(바닐라 JS). 프론트 프레임워크 쓰지 말 것.
- 외부 AI: Anthropic Claude API를 사용한다 (공식 python SDK `anthropic`, Messages API). **키는 강사마다 다르다.**
  · 서버에는 운영자 키를 두지 않는다. .env에 ANTHROPIC_API_KEY 를 넣는 구조 금지.
  · 강사가 화면에서 키를 입력하면 브라우저 localStorage 에만 저장하고, 매 요청마다
    HTTP 헤더 `X-Anthropic-Key` 로 보낸다. 서버는 요청 처리 중에만 메모리에 들고 있고,
    디스크·로그·캐시 파일·오류 메시지·예외 스택 어디에도 키를 기록하지 않는다.
    (로그 필터를 두어 `sk-ant-` 로 시작하는 문자열은 자동으로 `sk-ant-***` 로 가려라.)
  · 모든 API 호출은 services/claude_client.py 한 곳을 거친다. 호출 함수는 키를 인자로 받는다(전역 변수 금지).
    여기서 재시도, 타임아웃, 호출 횟수·토큰·예상 비용 기록, 응답 캐시를 처리.
  · 시스템 프롬프트(판정 기준 설명 + 예시 이미지)는 길고 매번 같으므로 프롬프트 캐싱(cache_control)을 켜서 비용을 줄여라.
  · 응답 캐시(data/api_cache/)는 이미지 해시+프롬프트 해시+모델명으로 키를 만들고, 강사 키는 캐시 키에
    포함하지 않는다(같은 사진을 두 강사가 올리면 두 번째는 호출 없이 재사용 → 비용 절약).
  · 키가 없는 요청도 실패하면 안 된다: API가 필요한 단계는 건너뛰고, 응답에 `api_skipped: true` 와
    한국어 안내("Anthropic 키를 넣으면 더 정확하게 지울 수 있어요")를 넣어라.
  · 키가 틀렸거나 잔액 부족(401 authentication_error / 429 rate_limit / 400 크레딧 부족)이면 규칙만으로 처리한 결과를 돌려주면서
    화면에 원인을 한국어로 알려라. 강사 키 문제로 서버가 500을 내면 안 된다.
  · 모델명은 config.yaml에 둔다: `claude.fast_model`(가성비 기본, Haiku 계열), `claude.quality_model`(고품질 옵션, Sonnet/Opus 계열).
    현재 Anthropic 문서에서 사용 가능한 모델 ID를 확인해 합리적인 기본값을 넣어라. 이미지·텍스트 모두 같은 모델로 처리.
    강사가 화면에서 "가성비/고품질"을 고를 수 있게.
  · 이미지를 보낼 때는 필요한 부분만 잘라서(crop) 보내고, 전체 페이지를 보낼 때는 긴 변 1500px 이하로 줄여라.
  · 구조화된 답이 필요한 호출은 반드시 **도구 호출(tool use)** 로 받아라: 원하는 JSON 스키마를 input_schema 로 가진 도구를 하나 정의하고
    tool_choice 로 그 도구를 강제 → 응답의 tool_use.input 이 곧 검증된 JSON. 자유 문장 파싱 금지.
  · 이미지는 base64 로 content 블록에 넣는다(image 블록 여러 개 + 번호 설명 텍스트를 한 메시지에).
  · 화면 오른쪽 위에 "오늘 API 사용: N회 / 약 ₩X" 표시. 단가표는 config.yaml에.
    사용량 기록(data/usage/{강사이름}.jsonl)에는 시각·모델·토큰·비용만 남기고 키는 절대 남기지 않는다.
- 강사 구분: 로그인 없음. config.yaml 의 `teachers` 목록(이름 문자열)에서 화면 위 드롭다운으로 자기 이름을 고르고,
  브라우저 localStorage 에 기억한다. 요청마다 헤더 `X-Teacher` 로 보낸다. 작업 폴더·최근 작업·사용량은 이름별로 나눈다.
  다른 강사의 결과물도 목록에서 볼 수 있어야 한다(내부용, "다른 강사 작업 보기" 토글).
- 접근 범위: 서버는 학원 내부 네트워크에서만 접속한다(`python run.py` 가 0.0.0.0:8000 으로 띄우고, README에
  "같은 와이파이의 다른 컴퓨터에서 http://서버IP:8000 으로 접속" 안내). 외부 인터넷에 노출하지 않는다는 전제로
  익명 ID·동의 절차·자동 삭제·URL 토큰 같은 공개 서비스용 보호 장치는 만들지 않는다.
- 데이터 보관: 올린 사진·처리 결과·교정 기록은 전부 서버에 보관하고 학습 데이터로 쓴다(삭제 정책 없음).
  첫 접속 안내문에 "올린 사진은 학원 서버에 보관되어 모델 개선에 쓰입니다" 한 줄만 보여준다.
- 픽셀을 실제로 지우거나 그리는 작업은 API에 시키지 않는다. 이미지 생성/편집 모델 사용 금지.
  (양식·수식·그래프가 바뀔 위험 때문.) API는 판정·검수·읽기·생성만 한다.
- 무거운 딥러닝(자체 학습)은 4단계 이전에는 쓰지 말 것. 1~2단계는 API 제외 CPU 처리 시간이 사진 한 장당 3초 이내.
- 코드는 초보자도 읽을 수 있게: 함수마다 한국어 docstring, 변수명은 줄이지 말고 풀어서 쓸 것
  (예: img 대신 original_image, thr 대신 threshold_value).
- 모든 파라미터(임계값 등)는 config.yaml 한 파일에 모으고, 각 항목 옆에 "이 값을 올리면 어떻게 되는지" 주석을 달 것.
- README.md에 "설치 → 실행" 을 명령어 3개 이내로, 그리고 "강사가 키를 넣는 방법"을 별도 절로 정리할 것.
  실행은 `python run.py` 하나로.
- 작업이 끝나면 (1) 무엇을 만들었는지 (2) 어떻게 테스트했는지 (3) API 호출이 어디서 몇 번 일어나는지
  (4) 키가 어디를 지나가고 어디에 절대 남지 않는지 (5) 알려진 한계를 한국어로 요약할 것.

[폴더 구조 — 이 구조를 지켜라]
clean_exam/
  run.py                 # 서버 실행 진입점
  config.yaml            # 모든 조정 가능한 값 (강사 목록, 모델명, 임계값, 단가표)
  app/                   # FastAPI 웹 서버
    auth_key.py          # 요청 헤더에서 강사 키·강사 이름을 꺼내는 의존성 (키 검증, 로그 마스킹)
  engine/                # 이미지 처리 엔진 (웹과 독립적으로 CLI로도 실행 가능)
  services/
    claude_client.py     # 모든 Claude 호출의 단일 창구 (키를 인자로 받음, 캐시·비용 기록 포함)
    prompts/             # API에 보내는 프롬프트 텍스트 파일들 (코드에 하드코딩 금지, 내가 고칠 수 있게)
  data/
    raw/                 # 올린 원본 사진 전부 (시험지별 폴더: raw/{시험지이름}/{강사}_{날짜}_{파일명}.jpg)
    teachers/{이름}/     # 강사별 작업 폴더 (cleaned, jobs.json, 최근 작업)
    labels/              # 학습 정답 마스크 (auto / multi / manual / corrections)
    synthetic/           # 합성 학습 데이터
    api_cache/           # API 응답 캐시 (키 무관, 이미지 해시 기준)
    usage/{이름}.jsonl   # 호출 기록 (시각, 모델, 토큰, 비용) — 키는 절대 없음
  models/                # 학습된 자체 모델 파일
  train/                 # 학습 스크립트
  tests/                 # 샘플 이미지 + 테스트 (API 호출은 mock으로 대체 가능해야 함)

[클로드 코드 작업 방식 — 항상 지켜라]
- 새 단계를 시작할 때는 먼저 "무엇을 어떤 순서로 만들지" 계획을 짧게 보여주고, 내가 "진행"이라고 하면 시작해라.
- 코드를 바꾼 뒤에는 반드시 직접 실행해서 확인해라: `pytest -q` 를 돌리고, 서버가 필요한 작업은 `python run.py` 로 띄워
  curl 로 API를 실제로 호출해 본 뒤 결과를 보고해라. "될 것이다"가 아니라 "돌려봤더니 이랬다"로 말해라.
- 이미지 처리 결과는 항상 원본/결과 비교 이미지(compare_*.png)를 만들고, 그 파일 경로를 알려줘서 내가 열어볼 수 있게 해라.
  네가 직접 그 이미지를 읽어 보고 "그래프가 끊겼다", "필기가 남았다" 같은 문제를 스스로 먼저 찾아 보고해라.
- 한 단계가 끝나면 git 커밋을 만들어라. 커밋 메시지는 한국어 한 줄("1단계: 규칙 기반 필기 지우기 엔진").
- 모르는 것(현재 Anthropic 모델 ID, SDK 사용법)은 추측하지 말고 docs.claude.com 에서 확인한 뒤 써라.
- 실제 Anthropic API를 호출하는 테스트는 내가 환경변수 ANTHROPIC_API_KEY 를 잠깐 넣어 줬을 때만, `--live` 플래그로 실행해라.
  그 외 테스트는 전부 mock. 키를 파일에 쓰거나 커밋하지 마라.
- 파일 삭제, 폴더 구조 변경, 의존성 추가는 하기 전에 한 줄로 이유를 말하고 해라.
